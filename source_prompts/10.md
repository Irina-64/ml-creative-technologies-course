Лабораторная работа 10. Выбор архитектуры и инструментов

Связь с лекциями. Лекции 5–6

Формируемые компетенции. ПК-1, ПК-1.1

Цель. Принять и обосновать архитектурное решение с учётом качества, данных, ресурсов, лицензий и рисков.

Исходная ситуация

Для музейного ассистента можно сопоставить поиск по ключевым словам, embeddings + retrieval, готовый API и RAG. Технология выбирается не по моде, а по способности дать проверяемый результат в заданных границах.

Порядок выполнения

1. Сформулируйте архитектурный вопрос, который должен быть решён до реализации alpha-версии.

2. Сравните минимум три релевантные альтернативы; среди них допустим мотивированный отказ от сложной технологии.

3. Определите критерии матрицы: ожидаемое качество, требования к данным, задержка, стоимость, лицензия, объяснимость, поддерживаемость, риски.

4. Оцените каждую альтернативу по единой шкале, укажите источники оценок и допущения.

5. Постройте схему выбранной архитектуры: вход, обработка, знания/модель, выход, журналирование, человек и fallback.

6. Зафиксируйте инструменты, версию и роль каждого; определите, что будет сделано без внешнего платного API.

Демонстрационный вариант выполнения

Ниже показан возможный результат по каждому шагу задания на сквозном учебном кейсе. Используйте его как ориентир уровня детализации, а не как готовое решение.

1. Архитектурный вопрос: использовать ли внешний мультимодальный API или локальный текстовый индекс для учебного архива без передачи изображений третьей стороне.

2. Сравнены keyword search, embeddings + локальный индекс и внешний API с мультимодальным поиском; все варианты описаны на одной странице матрицы.

3. Критерии: NDCG@10, latency, стоимость, передача данных вовне, лицензия, объяснимость и сложность поддержки.

4. Оценка: keyword search — NDCG 0,41 и низкая сложность; локальный индекс — 0,53 и 0,8 секунды; внешний API — ожидаемо выше качество, но не проходит ограничение на передачу архива.

5. Схема: запрос → проверка длины → embedding → локальный индекс → карточки с лицензией → выбор дизайнера; события ошибок пишутся в журнал; fallback — keyword search.

6. Выбран локальный индекс. Инструменты: Python, FAISS, sentence-transformers и локальный JSON-каталог; plan B — keyword baseline без платного API.

Что сдать

Матрица выбора; архитектурная схема; перечень инструментов и ролей; решение с обоснованием и перечнем допущений.

Критерии приёмки

Архитектура отвечает требованиям и ограничениям; решение проверяемо; альтернативы сопоставимы; указаны зависимость от внешних сервисов и plan B.

Типичные ошибки

Единственная альтернатива; оценки без оснований; схема только из названий библиотек; игнорирование стоимости и прав на модели/данные.
