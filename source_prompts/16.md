Лабораторная работа 16. Рубежная защита портфолио

Связь с лекциями. Лекции 1–8

Формируемые компетенции. ПК-1, ПК-1.1, ПК-3, ПК-3.1

Цель. Доказательно представить alpha-версию, её ограничения и обоснованный план развития; подтвердить индивидуальный вклад каждого участника.

Исходная ситуация

Защита строится как цепочка доказательств: проблема → знания и данные → baseline и эксперимент → архитектура → демонстратор → пользовательская проверка → риски → следующий шаг.

Порядок выполнения

1. Соберите портфолио артефактов ЛР-1–15; проверьте ссылки, версии, авторов и возможность открытия файлов.

2. Подготовьте презентацию, где на каждый важный тезис есть артефакт, метрика, пример или ограничение.

3. Сделайте demo-first сценарий: покажите работающий путь и один существенный отказ либо ограничение.

4. Подготовьте индивидуальную карту вклада: задача, артефакт, ссылка, решение, личное объяснение и следующий шаг.

5. Проведите внутреннюю репетицию: каждый студент объясняет собственные решения, данные, метрики и риски.

6. На защите честно назовите ограничения alpha-версии и сформулируйте один приоритетный эксперимент на следующий семестр.

Демонстрационный вариант выполнения

Ниже показан возможный результат по каждому шагу задания на сквозном учебном кейсе. Используйте его как ориентир уровня детализации, а не как готовое решение.

1. Портфолио содержит 15 документов, ссылку на репозиторий, dataset v0.2, Data Card, экспериментальный журнал, Model Card, риск-реестр и запись alpha-демо; все ссылки проверены с другого компьютера.

2. Презентация строится по схеме: проблема → знания → данные → baseline 0,41 → эксперимент 0,53 → архитектура → alpha-демо → четыре walkthrough → риски и backlog.

3. В demo-first части дизайнер вводит бриф и выбирает карточку; затем команда специально показывает недоступность индекса и запуск keyword fallback.

4. Карта вклада: студент 1 — Data Card и EDA; студент 2 — baseline, embeddings и журнал; студент 3 — интерфейс, walkthrough и backlog. У каждого есть commit и артефакт.

5. На репетиции каждый участник отвечает на вопрос по своей части: почему split выполнен по авторам, почему выбран NDCG@10, где расположен fallback и как обрабатывается лицензия.

6. Ограничения названы открыто: малый театральный сегмент и учебный архив. Следующий эксперимент — проверить новое название фильтра на пяти новых сессиях.

Что сдать

Презентация; ссылка на репозиторий; пакет артефактов ЛР-1–15; alpha-демо/запись; индивидуальные карты вклада.

Критерии приёмки

Цепочка решений прослеживается; демонстратор соответствует заявленному сценарию; каждый участник защищает личный вклад; ограничения и следующий шаг не скрыты.

Типичные ошибки

Презентация из общих слов; чужой код без понимания; нет ссылки на воспроизводимые артефакты; утверждение о готовом продукте без пользовательской проверки и рисков.
