Лабораторная работа 8. Метрики и анализ ошибок

Связь с лекциями. Лекция 4

Формируемые компетенции. ПК-1, ПК-1.1

Цель. Выбрать систему показателей, которая отражает полезность решения, и получить гипотезу по результатам анализа ошибок.

Исходная ситуация

Для выдачи референсов важнее получить нужный вариант среди первых результатов, чем угадать все метки. Поэтому для поиска уместны NDCG или MRR, а не только accuracy.

Порядок выполнения

1. Сформулируйте основную метрику, защитные метрики и порог приемлемости с учётом стоимости ошибок.

2. Постройте трек-специфичные артефакты: confusion matrix, таблицу ранжирования, распределение ошибок генерации или иную релевантную форму.

3. Разделите результаты по классам, сегментам, типам запросов и сложным сценариям.

4. Составьте taxonomy ошибок: описание, частота, вероятная причина, ущерб, следующий шаг.

5. Свяжите анализ с требованиями и пользовательской ценностью: какие ошибки недопустимы, а какие допустимы в alpha-версии.

6. Выберите одну проверяемую гипотезу для ЛР-9.

Демонстрационный вариант выполнения

Ниже показан возможный результат по каждому шагу задания на сквозном учебном кейсе. Используйте его как ориентир уровня детализации, а не как готовое решение.

1. Основная метрика — NDCG@10, защитные — Recall@10 и доля карточек без лицензии; порог alpha-версии: NDCG@10 не ниже 0,50, доля неясных лицензий — 0%.

2. Для 40 запросов построены таблица ранжирования, распределение NDCG@10 и таблица первых 10 результатов с отметкой релевантности эксперта.

3. Анализ проведён отдельно для русских и англоязычных запросов, концертных и театральных афиш, запросов по жанру и по настроению.

4. Taxonomy: не распознано настроение — 42%; ошибка языка запроса — 31%; лицензия не показана — 27%. Для каждой группы сохранено по 3 примера и вероятная причина.

5. Недопустимой признана ошибка с неясной лицензией, потому что она создаёт юридический риск; ошибка настроения допустима в alpha-версии, если пользователь видит альтернативы.

6. Гипотеза ЛР-9: text embeddings повысят NDCG@10 на 0,08, особенно для запросов по настроению; проверка идёт на том же наборе из 40 запросов.

Что сдать

Спецификация метрик; результаты baseline по сегментам; error taxonomy; вывод и карточка следующей гипотезы.

Критерии приёмки

Выводы не основаны на одной aggregate-метрике; у ошибок есть примеры и предполагаемая причина; следующий эксперимент связан с наблюдением.

Типичные ошибки

Выбор F1 «по привычке»; смешение ошибок модели и ошибок разметки; ручной отбор только красивых примеров; замена анализа списком чисел.

Самопроверка перед сдачей

Какая ошибка наиболее вредна пользователю и какая метрика или сегмент позволяет её заметить?
