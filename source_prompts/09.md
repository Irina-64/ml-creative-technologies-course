Лабораторная работа 9. Эксперимент с улучшением

Связь с лекциями. Лекция 5

Формируемые компетенции. ПК-1, ПК-1.1

Цель. Проверить одну техническую гипотезу в контролируемом эксперименте и принять прозрачное решение по её результату.

Исходная ситуация

Команда может предположить, что добавление метаданных улучшит поиск фрагментов видео. Чтобы проверить это, нельзя одновременно менять индекс, набор запросов и интерфейс.

Порядок выполнения

1. Запишите гипотезу в форме «изменение → ожидаемый эффект → метрика → условия».

2. Выберите один существенный фактор изменения: признаки, модель, retrieval, prompt template, стратегия обработки или версия данных.

3. Зафиксируйте контрольные условия: split, seed, набор запросов, метрики, окружение и baseline.

4. Ведите журнал эксперимента с датой, автором, конфигурацией, результатами, ссылкой на запуск и интерпретацией.

5. Сравните с baseline не только агрегированно, но и по существенным сегментам и типам ошибок.

6. Примите решение «включить / не включать / проверить дополнительно»; отрицательный результат оформите как полезный вывод.

Демонстрационный вариант выполнения

Ниже показан возможный результат по каждому шагу задания на сквозном учебном кейсе. Используйте его как ориентир уровня детализации, а не как готовое решение.

1. Гипотеза оформлена: добавление text embeddings к keyword baseline повысит NDCG@10 минимум на 0,08 при неизменных запросах, split и показателях.

2. Изменяется только ранжирование: вместо TF-IDF добавляется embedding-вектор описания. Данные, интерфейс и фильтры не меняются.

3. Зафиксированы dataset v0.2, 40 запросов, seed 42, NDCG@10 и Recall@10, версия библиотеки и конфигурация experiment_01.yaml.

4. В журнале записаны дата, автор, commit, параметры индексатора, NDCG@10 = 0,53, Recall@10 = 0,70, latency = 0,8 секунды и ссылка на результат.

5. Сравнение показало рост по запросам настроения с 0,29 до 0,50, но на англоязычных запросах сохранились ошибки карточек без лицензии.

6. Решение: принять embeddings для alpha-версии; проблему лицензий отнести к интерфейсу и правилам ЛР-12. Результат признан положительным, но не универсальным.

Что сдать

Карточка гипотезы; журнал эксперимента; конфигурация запуска; сравнительная таблица; интерпретация и решение.

Критерии приёмки

Меняется контролируемое число факторов; результат воспроизводим; вывод не преувеличивает слабый эффект; отрицательный результат не скрыт.

Типичные ошибки

Одновременная смена модели и данных; подбор параметров по test; отсутствие baseline в таблице; утверждение о причине без анализа.
