Лабораторная работа 13. Alpha-демонстратор

Связь с лекциями. Лекция 7

Формируемые компетенции. ПК-1

Цель. Объединить компоненты в alpha-версию, которая позволяет проверить один пользовательский сценарий от начала до конца.

Исходная ситуация

Для помощника автора подкаста сценарий может быть таким: загрузить brief, получить варианты плана, выбрать и отредактировать предложение, сохранить черновик. Публикация без автора не входит в границы alpha-версии.

Порядок выполнения

1. Выберите один ключевой end-to-end сценарий из ЛР-3 и подготовьте сценарий демонстрации.

2. Соедините вход, проверки, ML/GenAI-компонент, слой знаний, отображение результата и действие пользователя.

3. Реализуйте или убедительно смоделируйте состояния: ожидание, корректный результат, ошибка, недопустимый ввод, fallback.

4. Подготовьте тестовые данные, не содержащие секретов и лишних персональных данных.

5. Запишите демонстрацию длительностью до трёх минут; покажите один нормальный и один проблемный случай.

6. Составьте список известных ограничений и условий, при которых демонстратор нельзя использовать.

Демонстрационный вариант выполнения

Ниже показан возможный результат по каждому шагу задания на сквозном учебном кейсе. Используйте его как ориентир уровня детализации, а не как готовое решение.

1. Выбран сценарий: дизайнер вводит бриф, получает 10 результатов, открывает две карточки, исключает одну и сохраняет подборку.

2. Соединены форма брифа, валидация, search API, правило лицензии, карточка результата и действие «сохранить подборку».

3. Интерфейс показывает индикатор поиска, обычный результат, сообщение для пустого запроса, экран ошибки индекса и fallback по ключевым словам.

4. Для демо подготовлены 15 разрешённых тестовых карточек и три запроса; персональные данные и реальные закрытые материалы не используются.

5. В записи 2 минуты 40 секунд: показан успешный поиск, затем пустой запрос и сбой индекса с переходом к keyword search.

6. Ограничения: сервис работает только с учебным архивом, не подтверждает авторские права и не рекомендует карточки без лицензионного статуса.

Что сдать

Alpha-демо или API; сценарий показа; запись демонстрации; инструкция запуска; список известных ограничений.

Критерии приёмки

Проверяется пользовательская ценность, а не только качество модели; предусмотрен fallback; демонстрация воспроизводима; границы alpha-версии названы явно.

Типичные ошибки

Только notebook без сценария; скрытый ручной монтаж; демонстрация одного удачного случая; ошибка выдаётся за пустой корректный ответ.

Самопроверка перед сдачей

Может ли пользователь завершить полезное действие, если внешний сервис временно недоступен?
