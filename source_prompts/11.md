Лабораторная работа 11. Минимальный ML/GenAI-модуль

Связь с лекциями. Лекция 6

Формируемые компетенции. ПК-1, ПК-1.1

Цель. Реализовать минимальный рабочий компонент с явным интерфейсом, ограничениями входа и воспроизводимыми настройками.

Исходная ситуация

Для генератора аннотаций каталога модуль принимает описание экспоната и проверенные записи, формирует черновик и возвращает текст, ссылки на источники и статус, требующий проверки специалистом.

Порядок выполнения

1. Определите контракт компонента: валидный и невалидный вход, структура выхода, ошибки, лимиты, требования к данным.

2. Реализуйте путь «вход → модель/знания → структурированный выход» без скрытых ручных шагов.

3. Вынесите настройки, ключи и адреса сервисов из кода; не добавляйте секреты в репозиторий.

4. Подготовьте набор обычных, сложных и недопустимых входов. Для генеративного компонента добавьте фактологические и стилистические сбои.

5. Сохраните примеры запуска и результата; укажите версию модели, prompt template и источники контекста.

6. Дополните README установкой, запуском и способом воспроизведения тестов.

Демонстрационный вариант выполнения

Ниже показан возможный результат по каждому шагу задания на сквозном учебном кейсе. Используйте его как ориентир уровня детализации, а не как готовое решение.

1. Контракт: вход `{query: str}` длиной 1–300 символов; выход — массив `{id, title, score, license, status}`; ошибки `empty_query` и `query_too_long`.

2. Реализован endpoint `/search`: он валидирует JSON, строит embedding, обращается к локальному индексу и возвращает 10 структурированных карточек.

3. Модель, путь к индексу и лимит запроса вынесены в config.yaml; ключей внешних сервисов в проекте нет.

4. Набор тестов: обычный запрос, запрос с опечаткой, английский запрос, пустая строка, 500 символов и набор служебных символов.

5. Для запроса «постер для детского фестиваля» модуль вернул 10 карточек; две без лицензии получили `status: review_required`. В results сохранён JSON ответа.

6. README содержит установку зависимостей, команду запуска, пример curl-запроса и команду `pytest tests/test_search.py`.

Запускаемый модуль; контракт API или функции; примеры входов/выходов; набор сложных случаев; README; конфигурация без секретов.

Критерии приёмки

Компонент имеет понятный интерфейс; результаты структурированы; есть обработка неверного ввода; независимый запуск возможен по инструкции.

Типичные ошибки

Демо только в личной сессии; секрет в коде; свободный текст вместо проверяемого формата ответа; «промпт сработал один раз» вместо тестов.
