# Лабораторная работа 13

## Alpha-демонстратор

Методические указания по дисциплине «Проект — применение машинного обучения в креативных технологиях». Магистратура, второй курс, первый семестр курса (третий семестр обучения).

Связь с лекциями: Лекция 7. Компетенции и индикаторы: ПК-1.

## Цель

Объединить компоненты в alpha-версию, которая позволяет проверить один пользовательский сценарий от начала до конца.

## Исходная ситуация

Для помощника автора подкаста сценарий может быть таким: загрузить brief, получить варианты плана, выбрать и отредактировать предложение, сохранить черновик. Публикация без автора не входит в границы alpha-версии.

Вход для работы: артефакты предыдущих работ, прежде всего ЛР 12. Результат включается в портфолио и используется на следующих шагах.

## Что должно работать в alpha

Alpha-демонстратор соединяет компоненты в один сценарий. Пользователь должен отправить запрос, увидеть осмысленный результат, принять решение и получить подтверждение. Исходное задание допускает интерфейс или API; в этом демо реализован локальный API, который позволяет проверить все переходы без дополнительной веб-разработки.

Сбой и отсутствие совпадений различаются. При no_matches запрос обработан, но подходящих кандидатов нет. При fallback основной улучшенный путь отключён, а система использовала резерв. Если показывать оба случая как обычный пустой список, пользователь не узнает, что произошло.

## Развёрнутый порядок выполнения

Выберите историю из ЛР 3, назовите исходный запрос и полезное конечное действие. В поиске это выбор карточки, а не только печать векторов. Подготовьте последовательность действий и ожидаемые статусы до записи демонстрации.

Используйте тот же модуль, который проверялся в ЛР 11. Подключите каталог, словарь и обратную связь. Не меняйте модель или подменяйте ответ вручную для красивой записи. Если используется mock, покажите его границы явно.

### Шаг 3 Состояния

Покажите нормальную выдачу, отсутствие совпадений, ошибку ввода и резервный путь. Режим ожидания в API означает ожидание HTTP-ответа; графический индикатор в этом варианте не реализован. Отказ улучшенного пути воспроизводится специальным флагом, а не повреждением пользовательских файлов.

Используйте разрешённые учебные карточки и запросы без персональной информации. Укажите, какие результаты получены на объединённом каталоге, а какие — в независимом evaluation. Не сравнивайте метрики на validation с интерактивной выдачей all как равные эксперименты.

### Шаг 5 Запись

Запишите до трёх минут последовательного выполнения, включая нормальный и проблемный случай. В комплекте автоматическая запись терминального протокола настоящих HTTP-запросов сопровождается читаемой расшифровкой. Она не изображает пользовательское исследование. В студенческой работе допустима запись экрана или аналогичный проверяемый протокол демонстрации.

### Шаг 6 Ограничения

Назовите условия, при которых alpha нельзя использовать как готовый продукт. Объясните, что произойдёт при отключении улучшенного компонента. Проверьте запуск на чисто созданных данных и включите команды в сдачу.


## Полный демонстрационный вариант

### Артефакт Сценарий показа

1. Запустить локальный API и проверить /health.
2. Отправить «саксофон лаконичный» и показать источник и допуск первых карточек.
3. Выбрать P001 через /feedback с action=select и actor=designer_demo. Показать recorded и model_updated=false.
4. Отправить пустую строку и показать HTTP 400 с empty_query.
5. Отправить «jazz minimalist» и показать no_matches.
6. Запустить контролируемый резервный режим и повторить «джаз минимализм». Показать fallback и сохранённый полезный результат.

Нормальный сценарий завершается сохранением выбора. Проблемные случаи объясняют, когда уточнить запрос и когда система работает ограниченно. Используются только созданные для демо макеты.


### Артефакт Инструкция запуска и запись

```powershell
python -m demo.project run
python -m demo.record_demo
```

Вторая команда сама поднимает временный локальный HTTP-сервер, отправляет реальные запросы, сохраняет ответы и корректно останавливает его. Создаются demo/results/walkthrough.json, walkthrough.txt и walkthrough.cast. Формат cast содержит запись вывода терминала, которую можно воспроизвести совместимым проигрывателем asciinema; текстовая расшифровка не требует проигрывателя. В комплект включена также анимированная визуализация этой записи walkthrough.gif.

Для ручной демонстрации: `python -m demo.server --port 8765`. Для контролируемого отказа: `python -m demo.server --port 8766 --simulate-failure`. Это специально заданный отказ улучшения, а не доказательство обработки всех возможных аварий процесса или сети.


### Артефакт Фактический протокол

| Шаг | Путь | HTTP | Фактический ответ |
|---|---|---|---|
| Поиск | /search | 200 | ok: P001, P003, P005 |
| Выбор | /feedback | 200 | recorded: событие сохранено |
| Пустой запрос | /search | 400 | error: empty_query |
| Другой язык | /search | 200 | no_matches: пустой список |
| Резервный режим | /search | 200 | fallback: P001, P003, P005 |

### Артефакт Известные ограничения

Alpha использует 36 искусственных макетов, короткие русские описания и восемь соответствий словаря. Она не распознаёт визуальное содержание произвольного изображения, не подтверждает права и не доказывает экономию времени дизайнера. Скорость на промышленном архиве не измерена.

Сервис предназначен только для localhost. Нет аутентификации, графического интерфейса, промышленного журналирования, устойчивого многопользовательского хранилища и процесса утверждения правок. Нельзя выставлять этот http.server в открытую сеть. Указание роли в JSON не подтверждает полномочия человека.

При отказе словаря буквальный поиск остаётся доступен; синонимические запросы могут потерять результат. Пользователь видит fallback и может переформулировать запрос или перейти к ручному просмотру. При полном отказе процесса API недоступен: этот класс отказа не устраняется текущим fallback.
