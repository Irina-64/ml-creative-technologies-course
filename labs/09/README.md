# Лабораторная работа 9

## Эксперимент с улучшением

Методические указания по дисциплине «Проект — применение машинного обучения в креативных технологиях». Магистратура, второй курс, первый семестр курса (третий семестр обучения).

Связь с лекциями: Лекция 5. Компетенции и индикаторы: ПК-1, ПК-1.1.

## Цель

Проверить одну техническую гипотезу в контролируемом эксперименте и принять прозрачное решение по её результату.

## Исходная ситуация

Команда может предположить, что добавление метаданных улучшит поиск фрагментов видео. Чтобы проверить это, нельзя одновременно менять индекс, набор запросов и интерфейс.

Вход для работы: артефакты предыдущих работ, прежде всего ЛР 8. Результат включается в портфолио и используется на следующих шагах.

## Логика контролируемого эксперимента

Эксперимент проверяет конкретную гипотезу при сопоставимых условиях. Если вместе со словарём заменить данные, метрику и интерфейс, улучшение нельзя связать с одним изменением. Поэтому сначала фиксируют условие успеха, затем запускают варианты и сохраняют результат независимо от его привлекательности.

Validation служит для выбора решения. Test используется после выбора, иначе он превращается в ещё одну настроечную выборку. Повторный запуск детерминированного кода проверяет воспроизводимость, но не увеличивает число независимых наблюдений. Десять одинаковых запусков на тех же запросах не равны десяти исследованиям.

## Развёрнутый порядок выполнения

### Шаг 1 Формулировка гипотезы

Перенесите H1 из ЛР 8 в журнал до просмотра улучшенного результата. Укажите ожидаемый прирост в абсолютных единицах и защитные условия. Различайте прирост 0,10 NDCG и относительные 10 процентов: это разные утверждения.

### Шаг 2 Единственный изменяемый фактор

В демо меняется только нормализация токенов запроса по фиксированному словарю. TF-IDF, IDF, каталоги, сортировка и k остаются теми же. Сохраните оба режима в коде, чтобы baseline можно было повторить после улучшения.

### Шаг 3 Контроль условий

Зафиксируйте версию набора, параметры, хеш IDF, Python и команду запуска. Словарь должен иметь происхождение и версию. Нельзя добавлять в него неизвестные test-слова после итоговой оценки и продолжать считать test независимым.

### Шаг 4 Журнал запуска

Сохраните дату, автора запуска, конфигурацию, пути к результатам и решение. Для учебного комплекта автором кода является автоматизированная подготовка материалов; это не личный вклад студента. В своей сдаче студент фиксирует собственное изменение и объясняет его смысл.

### Шаг 5 Сравнение

Сравните общий результат и сегменты. Покажите хотя бы один изменившийся и один неизменившийся пример. Укажите, какие классы запросов не охвачены проверкой. На искусственном наборе идеальная метрика отражает простоту конструкции, а не способность понимать произвольные брифы.

### Шаг 6 Решение

Примите вариант, отклоните его или назначьте дополнительную проверку по заранее заданным условиям. Сформулируйте границы вывода. Отрицательный результат оформляется так же полно, как положительный: сохраняются настройки, метрики и объяснение следующего шага.


## Полный демонстрационный вариант

### Артефакт Карточка гипотезы и конфигурация

H1: фиксированный словарь улучшает синонимические запросы. Минимальный прирост validation NDCG@3 — 0,10; Recall не уменьшается; фильтр допуска остаётся обязательным. Изменяемый фактор: перед векторизацией заменяем термин на канонический. Контроль: та же версия 1.0, те же 12 validation-запросов, train-IDF, k=3 и правила tie-break.

```json
{"baseline":"tfidf", "candidate":"tfidf+lexicon",
 "k":3, "lexicon_version":"1.0", "data_version":"1.0",
 "selection_split":"validation", "final_split":"test"}
```

Словарь: саксофон → джаз; спектакль → театр; кинопоказ → кино; галерея → выставка; рейв → электроника; опенэйр → фестиваль; лаконичный → минимализм; насыщенный → детализация. Эти соответствия заданы для учебного каталога; например, «саксофон» не означает «джаз» во всех возможных произведениях.


### Артефакт Журнал и команды

Запуск E01, дата подготовки 29.10.2026. Исполнитель — автоматизированное учебное демо, без реальных участников. Команда: `python -m demo.project run`. Код: SearchEngine.vector, параметр expand. Все результаты: demo/results/summary.json и validation_baseline.csv, validation_improved.csv. Фактическая версия Python сохранена в environment.json.

Контрольный хеш IDF: 07064aaf25e399916f5a16fc75dc99f8cb3ae8be7019cadee6ae05f45920733f. Он относится к реализации 1.0; после изменения корпуса должен измениться и требует объяснения. Случайность отсутствует, поэтому повторный запуск даёт те же оценки.

### Артефакт Интерпретация и решение

Решение E01: включить словарь в учебную alpha, сохранив baseline как fallback. Заранее заданные условия H1 выполнены на искусственном наборе. Полный результат 1,00 объясняется тем, что каталог и запросы построены по простым согласованным шаблонам; статистическая значимость и эффективность на естественных брифах не устанавливались.

Ограничение test: группы карточек различаются, но языковые шаблоны повторяются. Следующий полезный эксперимент должен использовать независимо собранные естественные запросы, а не больше повторов текущего шаблона. Контрпример «jazz minimalist» остаётся без совпадений. При реальном ухудшении Recall или нарушении допуска решение должно быть «не включать», даже если средняя NDCG выросла.

## Критерии приёмки

Меняется контролируемое число факторов; результат воспроизводим; вывод не преувеличивает слабый эффект; отрицательный результат не скрыт.

| Критерий | Свидетельство в демо |
|---|---|
| Меняется контролируемое число факторов | Меняется только нормализация запроса |
| результат воспроизводим | Версии, хеш и команда |
| вывод не преувеличивает слабый эффект | Ограничение синтетического идеального результата |
| отрицательный результат не скрыт | Критерий отказа и сохранение всех результатов |
