# Лабораторная работа 6

## Разметка и подготовка данных

Методические указания по дисциплине «Проект — применение машинного обучения в креативных технологиях». Магистратура, второй курс, первый семестр курса (третий семестр обучения).

Связь с лекциями: Лекция 3. Компетенции и индикаторы: ПК-1.1, ПК-3.1.

## Цель

Сформировать версию данных и процедуру разметки, пригодные для честной оценки и повторного использования.

## Исходная ситуация

Если плакаты размечаются как «минималистичные» и «детализированные», инструкция должна объяснять, как работать с пограничным случаем, а не оставлять решение интуиции разметчика.

Вход для работы: артефакты предыдущих работ, прежде всего ЛР 5. Результат включается в портфолио и используется на следующих шагах.

## От понятия к воспроизводимой метке

Операционализация означает перевод понятия в процедуру наблюдения. Если два разметчика понимают «минимализм» по-разному, модель получает противоречивые примеры. Инструкция должна содержать признаки, порядок решения, пограничные случаи и способ отказаться от уверенной метки.

Согласие разметчиков оценивает устойчивость инструкции, а не её истинность. Два человека могут одинаково ошибаться. Простая доля совпадений понятна, но зависит от частот классов; коэффициент каппа дополнительно учитывает ожидаемое случайное согласие. На малой выборке оба показателя нужно интерпретировать осторожно.

## Развёрнутый порядок выполнения

### Шаг 1 Определения и границы

Для каждого класса укажите наблюдаемый признак, положительный и отрицательный пример. Запишите пограничное правило. В учебных макетах можно считать крупные фигуры, но нельзя переносить такой порог на реальные произведения как универсальную теорию композиции. Для поиска отдельно задайте шкалу релевантности запросу.

### Шаг 2 Инструкция и пилот

Дайте инструкцию новому разметчику и небольшой набор. Сначала он работает самостоятельно, затем вы обсуждаете непонятные места. Не исправляйте его ответы в процессе: так исчезнет информация о проблемах инструкции. Сохраните исходные и согласованные метки раздельно.

### Шаг 3 Независимая проверка

Попросите второго разметчика оценить ту же часть, не показывая ответы первого. Рассчитайте совпадения и разберите каждое расхождение. Если второго человека нет, согласуйте повторную отложенную разметку или экспертную ревизию; назовите ограничения такого контроля. Синтетические решения в демо не являются работой реальных разметчиков.

### Шаг 4 Спорные случаи и версии

Каждое расхождение внесите в журнал с первоначальными метками, решением и основанием. Если определение меняется, увеличьте версию инструкции и проверьте все затронутые объекты. Не заменяйте спорную метку произвольным большинством без объяснения.

### Шаг 5 Подготовка без утечки

Сначала исключите недопустимые данные и повторы, затем назначьте группы выборкам. Обучаемые преобразования рассчитывайте по train. В данном демо IDF использует только train-описания; словарь и правила фиксируются до выбора модели. Изменение test ради улучшения результата запрещено.

### Шаг 6 Итоговый паспорт

Сохраните версию набора, инструкцию, исходные и финальные метки, статистику согласия и код. Проверьте, что другой студент сможет повторить подготовку. Передайте полученный clean и split в ЛР 7.


## Полный демонстрационный вариант

### Артефакт Инструкция разметчика версии 1

Объект: геометрический учебный макет. Считать крупные круги композиции, не считать буквы заголовка. До трёх кругов включительно — «минимализм», четыре и более — «детализация». Если фигуры невозможно различить, поставить «спорный» и описать причину. Это правило только для данного набора.

Положительный пример минимализма: P001, два круга. Отрицательный: P002, семь кругов. Пограничные примеры: три крупных круга → минимализм; четыре → детализация; два круга и несколько декоративных точек → спорный до определения минимального размера точки в инструкции. Последний пример показывает необходимость дополнительного правила при расширении генератора.

Порядок: открыть изображение; проверить читаемость; посчитать объекты; присвоить метку; записать уверенность и комментарий; не смотреть метку другого разметчика. При расхождении сохранить оба ответа и передать на обсуждение.

Шкала релевантности поиску: 2 — верный жанр и минималистичный стиль; 1 — верный жанр, другой стиль; 0 — другой жанр. В демонстрационных запросах требуется минимализм. Для настоящих брифов критерии нужно расширить и согласовать с пользователями.

### Артефакт Версия набора и код подготовки

```powershell
python -m demo.project run
python -m unittest demo.test_project -v
```

Данные: demo/data/clean.json, версия 1.0, 36 карточек. Метки пилота: demo/data/annotations.csv. Код подготовки: функции generate и prepare в demo/project.py. Порядок проверки записи: права → описание → повтор хеша → включение. Порядок вычисления IDF: выделить train → посчитать частоты слов по документам → применить неизменные веса ко всем остальным частям.

Контроль test_idf_ignores_test заменяет test-описания новым словом и проверяет, что IDF не изменился. Контроль test_groups_do_not_overlap проверяет авторские группы. Такой тест проверяет конкретную возможную утечку, а не только наличие файла split.

## Критерии приёмки

Классы можно применить одинаково разными людьми; подготовка данных воспроизводима; неясные случаи документированы; test защищён от утечки.

| Критерий | Свидетельство в демо |
|---|---|
| Классы можно применить одинаково разными людьми | Инструкция, границы и примеры |
| подготовка данных воспроизводима | Детерминированный код и проверки |
| неясные случаи документированы | Два расхождения с сохранёнными метками |
| test защищён от утечки | IDF только train, тест неизменности |

## Типичные ошибки

Один пример вместо определения класса; исправления разметки без версии; нормализация на всём наборе до split; игнорирование несогласия экспертов.
